# Бот и мини-приложение для MAX

Подбор персонала прямо в мессенджере для небольших компаний без отдельного HR: пекарня, магазин, ферма, небольшая IT-контора.

Пользователь выбирает роль и сразу смотрит вакансии или анкеты — профиль можно создать позже. Чтобы откликнуться, разместить вакансию или пригласить работника, бот и мини-приложение просят создать профиль. Пока отклик не приняли обе стороны, телефоны скрыты; после взаимного одобрения контакты открываются, а работник попадает в кадры компании.

## Проверки

- **Компания — ЕГРЮЛ/ЕГРИП ФНС.** ИНН (с контрольными цифрами), ФИО руководителя и юридический адрес сверяются с записью на egrul.nalog.ru. Не прошедшая проверку компания может публиковать вакансии, но соискатели видят в них пометку «Компания не подтверждена». Если ФНС не ответила, проверка повторяется автоматически каждые 30 минут.
- **Работник — Госуслуги (ЕСИА).** Вход по OAuth 2.0 ЕСИА: ФИО, дата рождения, СНИЛС и контакты берутся из Госуслуг, запросы подписываются ГОСТ-подписью через сервис подписи. В каждой анкете видно, как она создана: «Подтверждено через Госуслуги» или «Заполнено вручную · Госуслуги не подключены».
- **Телефон — MAX.** В мини-приложении работник подтверждает номер через `requestContact`, сервер проверяет подпись MAX.

## Запуск

Токен бота кладётся в `.env` (в git не попадает), шаблон — `.env.example`.

```bash
cp .env.example .env
docker compose up -d --build
```

База создаётся пустой в `./data/data.json`, фото — в `./miniapp/uploads`. Снаружи работает nginx на портах 80/443, Node внутри контейнера — на 8080.

HTTPS для домена: `bash scripts/enable-https.sh ваш-домен.ru` — выпускает сертификат Let's Encrypt, включает 443 и прописывает `MINI_APP_URL`.

Без Docker: `npm install` и `node bot.js`, мини-приложение на `http://localhost:8080`, база в `./data.json`.

## Настройки .env

- `BOT_TOKEN` — токен бота MAX
- `MINI_APP_URL` — публичный `https://` адрес мини-приложения
- `MINI_APP_OPEN_BUTTON=1` — кнопка «Открыть приложение» в меню бота. Пока URL не привязан к боту в кабинете MAX, кнопка ломает отправку меню, поэтому по умолчанию она выключена
- `MINIAPP_DEV_USER_ID` — пользователь для локального открытия мини-приложения в браузере
- `ESIA_CLIENT_ID`, `ESIA_REDIRECT_URI` (`https://домен/esia/callback`), `ESIA_CERT_HASH`, `ESIA_SIGNER_URL` — подключение к ЕСИА; кнопка «Подтвердить через Госуслуги» появляется, когда заданы все четыре. `ESIA_SIGNER_URL` принимает `{"data": base64}` и возвращает `{"signature": base64}` — открепленную подпись ГОСТ Р 34.10-2012 сертификатом информационной системы
- `SFR_LABOR_BOOK_URL`, `SFR_LABOR_BOOK_TOKEN` — загрузка электронной трудовой книжки
- `NODE_TLS_REJECT_UNAUTHORIZED=0` — только для локальной сети с подменой сертификатов; в Docker-образ добавлены корневые сертификаты Минцифры для API MAX

## Сценарий проверки

Два аккаунта MAX.

1. Работник: роль «Работник» → «Найти работу» без анкеты → «Откликнуться» → бот просит создать анкету → анкета → отклик.
2. Работодатель: роль «Работодатель» → «Найти работников» без профиля → профиль компании с проверкой ЕГРЮЛ → вакансия с контактом сотрудника.
3. Работодатель принимает отклик — обоим приходят контакты, работник появляется в «Кадрах».
4. «Кадры» → стажировка или обучение для сотрудника.
5. То же самое в мини-приложении по кнопке «Открыть приложение».
