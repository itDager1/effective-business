# Найм в MAX

Бот и мини-приложение, чтобы небольшая компания без кадровика закрывала смену или сезон. Пекарня, магазин, ферма, кафе, маленькая контора.

Роль выбирается сразу, вакансии и анкеты можно смотреть без профиля. Анкета нужна, чтобы откликнуться, выложить вакансию или позвать человека. Телефон скрыт, пока обе стороны не согласятся. Потом контакты открываются, и работник оказывается в кадрах. Из кадров можно предложить стажировку или обучение.

## Как устроено

Один процесс на Node. Чат-бот через `@maxhub/max-bot-api`, рядом с ним HTTP-сервер мини-приложения. Страницы в `miniapp/`. База — json, фото лежат файлами.

В Docker снаружи nginx на 80 и 443, само приложение на 8080.

```bash
docker compose up -d --build
```

Остановить: `docker compose down`. Поднять снова: `docker compose up -d`.

Без Docker: `npm install` и `npm start`. Порт берётся из `MINI_APP_PORT`, если не задан — 8080, база тогда в `./data.json`.

Зависимости и версии в `package-lock.json`: `@maxhub/max-bot-api`, `dotenv`, `sharp`.

Сертификат для домена: `bash scripts/enable-https.sh ваш-домен.ru`.

## Настройки

`.env` в git не входит, образец — `.env.example`.

- `BOT_TOKEN` — токен бота из кабинета MAX
- `MINI_APP_URL` — адрес мини-приложения, для боя это https://max339.ru
- `MINI_APP_PORT` — порт приложения, в контейнере 8080
- `MINI_APP_OPEN_BUTTON=1` — кнопка «Открыть приложение» в меню. Само мини-приложение к боту уже привязано
- `MINIAPP_DEV_USER_ID` — чей пользователь открывается, если зайти в мини-приложение из обычного браузера
- `ESIA_CLIENT_ID`, `ESIA_REDIRECT_URI`, `ESIA_CERT_HASH`, `ESIA_SIGNER_URL` — Госуслуги. Кнопка есть только когда заполнены все четыре. На сервере их нет, анкета помечается как заполненная вручную
- `ESIA_SIGNER_URL` ждёт `{"data": base64}` и отдаёт `{"signature": base64}`, подпись ГОСТ
- `SFR_LABOR_BOOK_URL`, `SFR_LABOR_BOOK_TOKEN` — выписка трудовой. Сейчас пусто, человек дописывает записи сам
- `NODE_TLS_REJECT_UNAUTHORIZED` — в образе уже стоят корневые сертификаты Минцифры, для MAX это не нужно выключать

## Данные

Первый запуск создаёт пустую базу: в Docker это `./data/data.json`, без Docker — `./data.json` в корне. Фото: `./miniapp/uploads`.

Готовых тестовых анкет нет. Проверка идёт со своих аккаунтов MAX: сами заполняем анкету работника и профиль компании.

Компания сверяется живым запросом к egrul.nalog.ru: ИНН, руководитель, адрес с индексом. Если в ответе ФНС нет улицы, сравнивается регион. Если ФНС не ответила, проверка повторяется каждые 30 минут. Неподтверждённая компания вакансию опубликовать может, на ней будет пометка.

Города — справочник в `cities.js`, расстояние считается от города в фильтре или от города в анкете.

## Как посмотреть

1. Со своего аккаунта MAX выбрать «Работник», открыть вакансии без анкеты и нажать «Откликнуться». Бот попросит анкету, после неё отклик уходит.
2. Со своего аккаунта работодателя посмотреть анкеты без профиля, затем заполнить компанию. После сохранения бот сверяет её с ЕГРЮЛ.
3. Разместить вакансию, у неё отдельный контакт сотрудника.
4. Принять отклик. Обоим открываются телефоны, работник появляется в «Кадрах».
5. В кадрах предложить стажировку или обучение.
6. Тот же путь в мини-приложении: https://max339.ru

Пока согласия нет, телефон в карточке не показывается. После взаимного «да» показывается.

## Чего нет

Госуслуги написаны, но не включены: нет клиента ЕСИА и подписи. Трудовую из СФР не загружаем. Подтверждение телефона — это подпись номера аккаунта MAX, не смс. На большой поток один json-файл уже не подойдёт.
